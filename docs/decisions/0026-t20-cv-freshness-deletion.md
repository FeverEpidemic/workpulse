# Decision 0026 — T20 CV freshness dan deletion

Date: 3 Oktober 2026

Status: accepted for WorkPulse MVP v0.1 (local acceptance; see `docs/verification/T20-cv-freshness-deletion.md`)

References: PRD R03 (*CV needs review*), R09 (*Source edits trigger a reviewable refresh*), *CV freshness contract*, release scenario *edit a selected achievement after manual CV wording changes … delete its source*; User Flow F03, F07 langkah 5; Wireframe S04, S13 (state *changed source*, *manual override*, *deleted source*, *unconfirmed source*); Database Schema §2 (*Profile and context editing*), §5 (*Selection and freshness invariants*, *Deletion and export consistency*), §6 (atomic boundary delete, *simultaneous CV edits*); implementation plan §3 *Data karier* dan *CV*, §4 (*CV consistency … lock protocol*), §5 T20; handoff `docs/verification/T20-implementation-plan.md`; gate review `docs/verification/T20-gate-review.md`; decision 0024, 0025.

## Context

T18 menyediakan schema CV dan seleksi, T19 builder S13 dengan wording override. Sumber yang sudah dipilih tetap dapat diedit, di-reopen, atau dihapus. T20 membuat CV tahu kapan sumbernya berubah dan membuat pengguna menyelesaikan perubahan itu secara eksplisit, tanpa menimpa wording manual, serta membuat penghapusan sumber terpilih meng-invalidasi item CV dalam transaksi delete yang sama. Export, blokir export, dan S14 di luar scope (T21/T22).

## Keputusan

1. **Freshness dihitung saat dibaca, tidak ditulis saat sumber diedit.** RPC update sumber (`update_*`, `save_achievement`, `relink_*`, `update_activity`, `apply_ai_suggestion`, `commit_import_batch`) tidak diubah dan tidak menyentuh `cv_items`/`cv_documents`. *Alasan:* DB §5 "compute freshness from the live source revision"; menulis CV dari setiap update memaksa semua RPC itu masuk protokol lock CV dan membuka siklus lock.
2. **Satu definisi state di SQL.** `internal.cv_item_state(cv_items)`: `deleted` (`source_deleted` atau sumber tidak ada) > `unconfirmed` (achievement bukan `confirmed`) > `fresh` (revision live = `source_revision` **atau** `internal.cv_source_snapshot` live = `source_snapshot`) > `kept` (revision live = `acknowledged_revision`) > `changed`. `internal.cv_profile_state(cv_documents)` membandingkan tujuh field tampilan profil (`display_name`, `headline`, `summary`, `contact_email`, `phone`, `location`, `website`) dengan key sumber di `profile_snapshot` (abaikan `schema_version` dan `display_overrides`): sama → `fresh`; berbeda dan `profile_ack_revision = profiles.revision` → `kept`; selain itu `changed`. Helper `internal.cv_live_source`, `internal.cv_profile_display`. Semua helper internal tanpa grant (public/anon/authenticated/service_role dicabut). *Alasan:* revision saja menghasilkan *changed* palsu (metrics, skill link, `activity_id` dilepas, locale/timezone profil). Konsekuensi yang disengaja: konfirmasi ulang achievement tanpa perubahan field tampilan menghasilkan `fresh` (isi CV memang sama); konfirmasi ulang dengan perubahan → `changed`.
3. **Pemetaan aksi (disetujui pengguna, 2 Oktober 2026).** RPC menerima `keep`, `refresh`, `replace` untuk target `changed`/`kept`. UI: item `changed` tanpa override → *Refresh from source* (utama, `refresh`) / *Keep saved wording* (`keep`); item `changed` ber-override → *Keep my wording* (utama, `refresh`: detail lain diperbarui, override tetap) / *Replace from source* (`replace`); item `kept` → *Refresh from source* opsional; profil sama dengan `display_overrides`/`summary_override` sebagai wording; *Refresh all items without manual wording* = satu batch `refresh` untuk item `changed` tanpa override (dan tanpa draft lokal). `kept` untuk item ber-override tidak ditawarkan di UI. Aturan murni di `src/domain/cv/freshness.ts` (`availableActions`, `primaryAction`, `bulkRefreshResolutions`).
4. **Satu RPC resolusi: `public.resolve_cv_freshness(p_expected_revision integer, p_resolutions jsonb) returns table (cv_revision integer, added_parent_item_ids uuid[])`.** Array 1–200 `{target, item_id?, source_revision, action}`; key asing, item ganda, lebih dari satu entri profil → `INVALID_CV_INPUT` sebelum lock dokumen, tanpa nilai input di pesan. `source_revision` = revision live yang dilihat pengguna (profil: `profiles.revision`). Semua validasi di bawah lock sebelum write; satu `update cv_documents` di akhir (satu revision per batch). `keep` → `acknowledged_revision` = live; `refresh` → `source_snapshot`/`source_revision` = live, `acknowledged_revision = NULL`, `override_text` tidak disebut; `replace` → refresh + `override_text = NULL`. Profil: `keep` → `profile_ack_revision`; `refresh` → tujuh key sumber diganti nilai live, `schema_version`/`display_overrides` tetap, `profile_source_revision` = live; `replace` → juga menghapus `display_overrides` dan `summary_override`. Refresh achievement yang parent-nya berpindah ke project/experience yang belum terpilih menambah parent dalam transaksi yang sama (`internal.cv_append_item`, sama dengan `select_cv_source`).
5. **Penolakan.** `source_revision` ≠ live → `CV_SOURCE_CHANGED`; `expected_revision` CV basi → `STALE_REVISION`; target `fresh`/`deleted`, `keep` atas `kept`, atau `replace` tanpa override → `CV_RESOLUTION_INVALID`; `unconfirmed` → `CV_SOURCE_INELIGIBLE`; item akun lain atau ID acak → `CV_ITEM_NOT_FOUND` (tak terbedakan). Satu resolusi invalid membatalkan seluruh batch.
6. **Protokol lock (memperluas decision 0024 poin 10).** Semua jalur yang sadar CV: profil `for share` → `cv_documents for update` → item yang disentuh `for update` urut `id` → sumber `for share` urut tipe kanonik **experience → project → achievement → education → skill → certification**, masing-masing urut `id`. Parent achievement yang di-refresh dibaca tanpa lock, dikunci sebelum achievement, lalu dibandingkan ulang (berpindah → `CV_SOURCE_CHANGED`). Urutan sumber ini sama dengan `relink_achievement_project`, `relink_activity_project`, `delete_activity`, dan `delete_project` T09 (experience → project → activity → achievement). `commit_import_batch` mengambil profil `for update` lebih dulu dan tidak pernah menunggu dokumen CV, sehingga konsisten.
7. **Jalur delete sumber mengunci CV lebih dulu (disetujui pengguna).** `internal.cv_lock_for_source_change(user_id)` (profil `for share` → `cv_documents for update`, NULL tanpa CV) dipanggil di `delete_experience`, `delete_project`, `delete_achievement`, dan `internal.delete_foundation_record` (education, certifications, skills) setelah validasi auth dan sebelum lock sumber pertama. Bila sumber yang dihapus direferensikan item CV, satu `update cv_documents set updated_at = updated_at` setelah delete menaikkan revision CV dalam transaksi delete. FK `on delete set null` + trigger `guard_cv_item_row` T18 tetap menandai `source_deleted` dan mempertahankan snapshot serta `override_text`. Body fungsi lain identik dengan definisi terakhir (T09, foundation fix): signature, nilai kembali, kode error, grant, dan comment tidak berubah. Akun tanpa CV tetap dapat menghapus; delete sumber yang tidak terpilih tidak menaikkan revision CV. *Alasan:* rencana §3 menuntut invalidasi dan increment revision CV di transaksi delete; lock dokumen di depan menserialisasi delete dengan `remove_cv_item`/`save_cv_edits`/`resolve_cv_freshness` per akun.
8. **`select_cv_source` parent-dulu (disetujui pengguna).** Achievement dibaca tanpa lock untuk menemukan parent, parent dikunci `for share`, lalu achievement, lalu parent dibaca ulang; berpindah → `CV_SOURCE_CHANGED` (dapat diulang). Perilaku lain identik; `cv_selection.test.sql` hanya disesuaikan pada literal revision (lihat *Konsekuensi*). *Alasan:* T18 mengunci achievement lalu parent, berlawanan dengan relink.
9. **Deleted dan unconfirmed tidak punya aksi resolusi.** Diselesaikan lewat *Remove* (`remove_cv_item` T18) atau perbaikan sumber; item unconfirmed menautkan `/achievements/<id>`.
10. **RPC baca.** `public.get_cv_freshness()` (`target`, `item_id`, `state`, `live_revision`, `live_snapshot`; snapshot hanya untuk `changed`/`kept`, berisi field tampilan saja) dan `public.get_cv_review_summary()` (`has_cv`, `review_count` = item `changed`/`deleted`/`unconfirmed` + 1 bila profil `changed`, `available_count` = achievement `confirmed` tanpa item CV). `security definer`, `stable`, `auth.uid()`, tanpa lock, akun `deleting` → tanpa baris, execute hanya `authenticated`.
11. **Dashboard S04 (disetujui pengguna).** `get_dashboard_summary` T12 tidak diubah; `dashboard-service.ts` memanggil `get_cv_review_summary` paralel. Dua check terpisah di *Needs attention*: `dashboard.checkCvReview{One,Other}` → `/cv#cv-review`, `dashboard.checkCvAvailable{One,Other}` → `/cv#cv-pool-achievements` (pool dibuka saat tiba). Tampil hanya bila > 0; tanpa CV, *available* = jumlah achievement confirmed. RPC gagal → `UNAVAILABLE` seperti check lain.
12. **Draft T19 dilindungi (disetujui pengguna).** Aksi review untuk target yang wording-nya belum disimpan nonaktif dengan alasan terlihat (*Save or discard your wording first.*, `aria-describedby`); bulk refresh melewati item ber-draft. Setelah resolusi data dimuat ulang lewat jalur `syncDraft` T19 sehingga draft target lain tetap. `CV_SOURCE_CHANGED` → reload + notice *The record changed again*.
13. **Preview tetap dari data tersimpan.** `buildCvPreviewModel` tidak menerima state freshness; preview berubah hanya karena snapshot tersimpan berubah setelah `refresh`/`replace`.
14. **UI S13.** Badge teks (*Source changed*, *Saved wording kept*, *Source deleted*, *Source unconfirmed*, bersama *Manual wording*); ringkasan `#cv-review` (*N items need review*, tautan per item, bulk refresh bila ada kandidat); tombol *Review change* (`aria-expanded`/`aria-controls`) membuka panel `cv-review.tsx` yang membandingkan *Saved on CV* dan *Current source* hanya untuk field tampilan yang berbeda (tanggal mengikuti locale CV, konten tidak diterjemahkan), catatan perubahan konteks, dan wording manual; live region mengumumkan hasil; fokus kembali ke tombol review, lalu ringkasan, lalu heading. Aturan state UI murni di `cv-builder-state.ts` (diuji unit; proyek tanpa DOM test environment, decision 0025 poin 12).
15. **Kode error baru.** `CV_SOURCE_CHANGED` (service `SOURCE_CHANGED`, `cv.error.sourceChanged`, action `CONFLICT`), `CV_RESOLUTION_INVALID` (service `RESOLUTION_INVALID`, `cv.error.resolutionInvalid`, action `VALIDATION`). Kode T18/T19 dipakai ulang. Action me-revalidate `/cv` dan `/dashboard` (route dashboard nyata; rencana menulis `/`) hanya setelah sukses; satu correlation ID per request.
16. **Nomor.** Migration `20261004090000_t20_cv_freshness_deletion.sql` (parity 30/30, tanpa tabel/kolom baru); pgTAP `cv_freshness.test.sql`; integration `cv-freshness.test.ts` (`test:integration:cv-freshness`); E2E `cv-freshness.spec.ts` (`test:e2e:cv-freshness`, `playwright.cv-freshness.config.ts`, port 3013).

## Konsekuensi pada suite lama

Keputusan 7 dan 11 mengubah dua fakta yang dianggap tetap oleh suite lama; assertion intinya dipertahankan, hanya ekspektasi yang bergantung pada fakta lama disesuaikan:

- `supabase/tests/database/cv_selection.test.sql` bagian 8: literal revision CV 17/18 diganti revision dokumen saat itu (+1), karena enam delete sumber terpilih kini menaikkan revision.
- `tests/integration/cv-selection.test.ts`: race reorder vs `delete_experience` — reorder yang kalah kini `CONFLICT` (`STALE_REVISION`); posisi tetap rapat dan item terhapus tetap `source_deleted`.
- `tests/e2e/m2-manual-journey.spec.ts`: dashboard M2 tidak lagi "No checks need attention." karena achievement confirmed yang belum di CV menjadi check *available* (R03); assertion evidence/outcome kosong dipertahankan.

## Alternatif yang ditolak

Menulis `cv_items`/`cv_documents` dari setiap RPC update sumber; trigger update CV pada tabel sumber (siklus lock sumber → CV); perbandingan revision murni (changed palsu); refresh otomatis atau notifikasi; mengubah `get_dashboard_summary` (drop/recreate return type); aksi Keep untuk deleted/unconfirmed; RPC resolusi per item (revision berlipat); kolom/tabel baru.

## Seam

- **T21:** validasi request export memakai `internal.cv_item_state`/`internal.cv_profile_state` yang sama di bawah lock dengan urutan keputusan 6 (profil → dokumen → item → sumber kanonik). `changed` memblokir; `kept` lolos (Keep saved wording eksplisit, F07); `deleted`/`unconfirmed` memblokir sampai Remove atau perbaikan sumber; profil `changed` memblokir. Snapshot export dibangun dari `source_snapshot`/`override_text`/`profile_snapshot` tersimpan.
- **T22:** S14 menautkan setiap blokir freshness ke `/cv#cv-review` (dan item ke `#cv-item-<id>`).
- **Jalur delete baru:** setiap RPC baru yang menghapus experience/project/achievement/education/skill/certification wajib memanggil `internal.cv_lock_for_source_change` sebelum lock sumber pertama dan menaikkan revision CV bila item terdampak.

## Batas

Bukti lokal; tidak ada deployment. Race diuji dengan dua session nyata ×3 putaran per skenario pada satu proses Node (tidak deterministik, bukan stres berskala). `get_cv_freshness` menghitung snapshot live per item saat dibaca; biaya pada 200 item diukur di T24.
